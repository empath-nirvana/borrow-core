# #769: `Fs`, files as the platform's effect

Scope for #769, written before any code, read at `origin/main` dd4433ea. `Net` (#597) follows on
the same pattern. Section 10 records the review.

**Kernel target.** `Fs` is a platform effect on the existing capability pattern (SPEC §11, §34): a
cell with opaque content (`VTy.opq .fs`), a model, and externs whose models meet their contracts
(`*_meets`, `stdModel`, so `ExternsMeet`, `externs_every_run` and `io_every_run` cover them). A
file is a declared no-drop type (SPEC §42, `must_close`, decision of #746). No new kernel former,
typing rule or machine step. `Core/Opaque.lean` gains one opaque kind, as §34 added `clock` and
`args`. If anything else in `Core/`, `Paper/` or `Support/` has to change, the work stops and
reports.

## 1. The objects

In `lib/fs.bc`, a new library module (`include fs`). It is not part of `lib/sys.bc`: its
constructor names (`Reading`, `NotFound`, …) would otherwise be in every I/O program's scope.

```
-- A file's handle, open until a `match` consumes it (the ops' clauses, and `close`).
data File = { must_close(close) fd: i32 }

-- How a file is opened: for reading (it must exist), or for writing (created, or truncated).
data Mode = Reading | Writing

-- Why an operation failed.
data FsError = NotFound | Denied | IsDir | BadFile | TooBig | Other(i32)

effect Fs {
  fn fs_open(path: string, mode: Mode) -> string * (File + FsError)
  fn fs_read(f: File, b: string) -> File * (string * (i32 + FsError))
  fn fs_write(f: File, b: string) -> File * (string * (1 + FsError))
  fn fs_size(f: File) -> File * (i32 + FsError)
  fn fs_close(f: File) -> 1 + FsError
}
```

- **Answering, every one** (SPEC §34): each answers at once and its clause runs in place.
- **Owned buffers (decision 71).** Every buffer an operation reads into or writes from is a
  `string` (`buf u8`) moved into the operation and handed back with the answer, error or not.
  The path is moved in and handed back the same way. No operation's signature takes a borrow, so
  an async handler (#750 unit B) serves the same signatures with the buffer owned while the
  operation is pending. The blocking platform's clause lends the buffer to its extern for the one
  call inside the clause; that lend ends before the clause answers.
- **The file is moved in and handed back** by every operation but `fs_close`, which consumes it.
  An operation's error does not lose the file: it comes back beside the error.
- **`File` is a declared no-drop type.** `fd` is marked `must_close(close)`: the field is
  `i32 * tok`, the constructor mints the token, a `match` burns it (D4, E7, M5). So a `File` is
  used exactly once: never copied, never dropped by the checker, never live across a computation
  that may abort (`decl_linear`, `decl_not_ownFree`). The refusals name `close`.
- **The descriptor is an `i32`, not a cell** (the trade under *Forging*). A file is no heap object (Rust's `File` is a
  descriptor), and a fake handler can make one (section 7). SPEC §11 *Designed, not built* says
  "`Fs` (open yields an `Input`/`Output`, close consumes it)"; that would cost a cell per file and
  no handler but the platform could make one. The entry amends that line.
- **Forging, and what linearity guarantees.** A declared type's constructor is public: any code
  can write `File { fd: 7 }`, or `match` a file, keep its `fd` and build a second `File`. After one
  copy is closed the descriptor number may be reused by the next `open`, and the stale copy then
  names the new file. So the guarantee is **each `File` value is consumed exactly once** (closed on
  every exit, never dropped, never live across an abort), not "each descriptor is closed once".
  What closes the gap is constructor privacy (an abstract type, only `lib/fs.bc` building a
  `File`), which the language does not have yet: *Open*. The trade: a cell (`ref input`) would be
  unforgeable, since no source builds an opaque value, but costs an allocation per file (Rust's
  `File` has none) and no handler but the platform could make one, so `Fs` could not be faked.
  No descriptor is special-cased: refusing `0`, `1`, `2` would cover a few descriptors and leave
  the rest (Wasm's preopens among them, which a forged file can close) as exposed, so the gap is
  stated once, as the missing constructor privacy.

## 2. The laws (SPEC §34 *Laws*, new bullet)

Every operation may answer an error instead (`FsError`): the laws say what an answer that is not
an error means.

- `fs_open(p, Reading)` opens the existing file at path `p` for reading; `fs_open(p, Writing)`
  creates it, or truncates it, for writing. It answers a file, or why not.
- `fs_read(f, b)` reads into `b`'s spare capacity (from its length to its capacity), appending: at
  most the room, at least one byte while the file has more. It answers the count: `0` only at the
  end, or when the buffer has no room (then it reads nothing, with no system call).
- `fs_write(f, b)` writes every byte of `b`, in order.
- `fs_size(f)` answers the file's size in bytes when it is asked; a size of `2^31 − 1` or more is
  `TooBig` (a `buf` is indexed by `i32`, and `read_all` needs one byte of room past the size).
- `fs_close(f)` ends the file. An error there still ends it.
- Every operation hands back what it was given (the path, the buffer, the file) unchanged except
  for what the law says it does to the buffer.

## 3. The library (`lib/fs.bc`)

Raising forms over the operations (`Fail[FsError]`; decision: errors are a control-flow effect):

```
fn open(path: string, mode: Mode) -> string * File with Fs, Fail[FsError]
fn read(f: File, b: string) -> File * (string * i32) with Fs, Fail[FsError]
fn read_all(f: File) -> File * string with Fs, Fail[FsError]
fn write(f: File, b: string) -> File * string with Fs, Fail[FsError]
fn close(f: File) -> 1 with Fs, Fail[FsError]
```

- `read(f, b)` clears `b` and reads into it (`fs_read`): up to its capacity. A buffer of
  capacity `0` is given 4096 first (one allocation, which a caller avoids by passing capacity).
- `read_all(f)` sizes the file (`fs_size`), makes one buffer of the size plus one, and reads into
  it until a read answers `0`, growing it when it is full (`grow` to twice the capacity plus 4096,
  capped at `2^31 − 1`), so a file that grew, or one whose size reads `0` (a pipe),
  is read to its end. It raises `TooBig` (after closing the file) before the buffer would pass
  `2^31 − 1` bytes. On a regular file whose size
  held: one `fstat`, two `read`s (the data, then the `0` that confirms the end), one allocation.
  Rust's `fs::read` does the same.
- **Every loop over a file is counted, and running out is visible**: `for _ in 0..fs_max_reads {
  … break at the end … } else { … }`, never `loop`. A `loop` is codata (`unfold`) whose close
  branch discards its state at `F 1`, and a `File` has no derived drop, so the checker refuses a
  `File` in it (checked; `corpus/reject/fs-loop.bc` pins the refusal, whose message names the
  token's type, not `close`: the loop sugar's message, accepted as is). A counted loop has no close
  branch. `fs_max_reads` is `2^31 − 1`, fuel: a regular file ends long before, but a FIFO or a
  device such as `/dev/zero` may not, so the `else` arm (the fuel ran out) closes the file and
  raises `TooBig`; nothing truncates silently. `read_all` and `fs-cat` are written so, and
  `fs-fake` runs a loop with a small bound into its `else`.
- **Two files: a raise is handled while the other is open.** The raising forms close the file they
  were given before they raise. A second file the caller holds would be live across that raise, so
  the checker refuses an unhandled raising call while another file is open (`decl_not_ownFree`),
  the second `open` included. SPEC §42's pattern serves: the raising call under a local handler,
  `with to_result { read(f, b) }`, whose sum the caller matches, closing the other file before it
  raises; or the operations, whose sums the caller matches, raising once both files are closed.
  `corpus/fs-fake.bc`'s `copy_file` is written over the operations (a `for` that moves a file
  into a handled block and does not get it back on the error arm is not expressible with `let
  mut`); `corpus/reject/fs-two-files.bc` is `copy_file`
  with an unhandled raising call while a file is open, refused with the message naming `close`.
  `finally` does not serve (no I/O in a finaliser, SPEC §42 *Open*).
- **On an error, the operation's file is closed before the raise.** `read`, `read_all` and
  `write` call `fs_close` on the file the operation handed back (its own error ignored), then raise
  the operation's error. So a `File` is consumed on every exit of every library function, and a
  caller that threads it through these functions never holds it across an abort. A caller who
  wants to keep the file after an error uses the operations, which hand it back.

## 4. The platform handler

`wasi_fs` (in `lib/fs.bc`, beside the effect, so that only a program that includes `fs` has it in
its table), a lent handler on the capability's cell, `handler wasi_fs(&mut c: fs): Fs`. Each
clause:

1. takes the file apart (`match f { File { fd } -> … }`, burning its token);
2. lends the buffer (or path) for one call: `borrow imm s { v -> … }` for a path or a write;
   `borrow mut a { v -> match split_at_mut(v, n) { inl (h, t) -> … } }` over the spare capacity
   for a read (`lib/textio.bc`'s `input_chunk`, verbatim);
3. calls one extern on the lent cell;
4. rebuilds `File { fd }` (minting a token: a unit-class cell, as in `decl-txn`, counted `0`) and
   maps the extern's `i32` answer to the sum: `n ≥ 0` is the answer, `-k` is `FsError` kind `k`.

The ambient table (`platformEffects`) gains `("Fs", "fs", "wasi_fs")`; `main`'s capability externs
gain `fs : ref fs`; the harness gains `mk_fs : !(1 => ref fs)` and `take_fs : !(ref fs => i32)`
(reserved, as `mk_clock`).

## 5. The externs, their contracts and models

Opaque kind `fs`: `Opaque.Holds .fs v ⇔ ∃ n, v = i32[n]`. Representation `I32` (`vC_fsRep`). The
cell's content is the model's; the runtimes do not read it.

| extern | type | model (the empty file system) |
|---|---|---|
| `file_open` | `!(all 'a < top. all 'b < top. mut 'a fs * (array_imm 'b u8 * i32) => mut 'a fs * i32)` | forget the view; `-1` (not found) |
| `file_read` | `!(all 'a < top. all 'b < top. mut 'a fs * (i32 * array_mut 'b u8) => mut 'a fs * (array_mut 'b u8 * i32))` | the view back; `-4` (bad file) |
| `file_write` | `!(all 'a < top. all 'b < top. mut 'a fs * (i32 * array_imm 'b u8) => mut 'a fs * i32)` | forget the view; `-4` |
| `file_size` | `!(all 'a < top. mut 'a fs * i32 => mut 'a fs * i32)` | `-4` |
| `file_close` | `!(all 'a < top. mut 'a fs * i32 => mut 'a fs * i32)` | `-4` |
| `mk_fs`, `take_fs` | `!(1 => ref fs)`, `!(ref fs => i32)` | `alloc i32[0]`, `free` |

Each answer `≥ 0` is the result (a descriptor, a count, a size, `0`). A negative answer is an
error: `-1` not found, `-2` denied, `-3` a directory, `-4` a bad file, `-5` too big, and
`-(16 + c)` any other,
`c` the host's own error number (libc `errno` natively, WASI's `errno` on Wasm), which `Other(c)`
carries for a message; it differs between hosts, so a program whose output must agree across
targets prints the kind, not `c`. The model is a host with an empty file system: every open is
refused as not found (for writing too: `open(2)` with `O_CREAT` answers `ENOENT` when the
directory is not there, and there is none), and every descriptor is bad. It is lawful because
every law allows an error, and every stage that runs the model (the source, the closure and flat
IRs' interpreters, the new backend's interpreters) agrees with it. The claimed contract of each
extern is its type's relation (`*_meets`), not the laws; models are chosen by type (`stdModel`),
so `file_size` and `file_close`, of one type, share one model and one proof (`fileFd_meets`), and
`bcc trusted` says so.

`fileOpen_meets`, `fileRead_meets`, `fileWrite_meets`, `fileFd_meets` (size and close share a type
and a model), `mkFs_meets`, `takeFs_meets` (`Core/Stdio.lean`): each model is a `CDerives`
derivation at the representation, so the Fundamental Property puts it in the relation, and the
relation at the extern's type is the same (`cC_…`), as §34's. `stdModel` gains them, so
`stdModel_meets`, `externsMeet_of_model`, `io_every_run` and `IORun.every_run` cover a program
that uses `Fs`. `bcc trusted` lists each with its proof name and host:

| extern | host implementation | level |
|---|---|---|
| `fs` | the heap cell `run_io` makes by `mk_fs`; the file system is the host's | assumed (1) |
| `file_open` | libc `open(2)` (`O_RDONLY`, or `O_WRONLY \| O_CREAT \| O_TRUNC`, `0644`, `O_CLOEXEC`); WASI `path_open` under a preopened directory | assumed (1) |
| `file_read` | one `read(2)` / `fd_read` into the view | assumed (1) |
| `file_write` | `write(2)` / `fd_write` of the view, again after a short write | assumed (1) |
| `file_size` | `fstat(2)` / `fd_filestat_get` | assumed (1) |
| `file_close` | `close(2)` / `fd_close` | assumed (1) |
| `mk_fs`, `take_fs` | a fresh heap cell holding `0`; freed | assumed (1) |

Assumed, not interpreter-checked: the interpreters run the model, whose file system is empty, so no
interpreter exercises a host file.

## 6. The targets

**One system call per operation.** Each extern is one system call (`open`, `read`, `fstat`,
`close`), but `file_write`, which calls `write` again after a short write (none on a regular file),
and `file_open` on Wasm (below). No glue: each runtime function is the extern's host
implementation, and nothing sits between it and the checked term but the clause. No hidden copy:
`file_read` reads into the caller's buffer, `file_write` writes from it. The one copy is the
native path's: `open(2)` takes a NUL-terminated path, so the runtime copies the path's bytes into a
stack buffer of `PATH_MAX` (a path that does not fit is `TooBig`; one holding a `NUL` byte names no file, `NotFound`); Rust copies it
too. WASI `path_open` takes the bytes and length, no copy.

**Native (`Backend/Native/Runtime.lean`).** `bc_file`, one entry with an operation code, over libc, `errno` mapped to the kinds (`ENOENT`, `ENOTDIR` → 1;
`EACCES`, `EPERM`, `EROFS` → 2; `EISDIR` → 3; `EBADF` → 4; a size past `2^31 − 2` → 5; any other `c` → `-(16 + c)`). `EINTR` is
retried by `open`, `read`, `write` and `fstat`, never by `close`: the descriptor is released
whatever `close` answers, and a retry could close another file's. Paths are the process's: relative to
its working directory, with the process's authority.

**Wasm (`Backend/Wasm/Runtime.lean`).** WASI preview 1 opens only under a preopened directory.
`$fs_open` resolves the path against the preopens as wasi-libc does: it walks descriptors `3, 4,
…` while `fd_prestat_get` answers a directory, and takes the one whose name is the longest prefix
of the path ending at a `/` or at the path's end, a name `.` (`--dir .`) being the empty prefix of
every relative path (so an absolute path is matched against the absolute names, and `foo/x`
against `foo` or `.`); it opens the rest of the path relative to it with `path_open` (no symlink
following beyond WASI's default, `oflags` `CREAT | TRUNC` for writing, rights `fd_read`/`fd_seek`/
`fd_filestat_get` or `fd_write`). No preopen covers the path: `NotFound`: no file the program can name is there.
The walk is `fd_prestat_get` and `fd_prestat_dir_name` per preopen, at each open (a handful of
calls, none per byte); caching it is *Open*. An empty path is `NotFound` on both targets. `bcc run --dir <host-dir>` passes `--dir <host-dir>` to
`wasmtime` (repeatable); without it no directory is preopened and every open is `NotFound`.

**The interpreters** (closure IR, flat IR, `Backend2`'s) run the model: `file_open` answers `-1`,
the others `-4`. They hold no host file.

**`Backend2`.** The same primitive in its syntax, interpreters, layout and lowering, if it fits the
unit; otherwise its corpus lines for the new programs go on its known-failures list with this
unit named (`docs/compiler.md` §4.3). Decided while building and stated in the PR.

## 7. The programs and the test harness

- `corpus/fs-cat.bc`: prints the file named by its first argument, in chunks of one buffer of
  64 KiB reused across reads; on an error prints `fs-cat: <path>: <kind>` on standard error.
- `corpus/json-field.bc`: reads the JSON file named by its first argument whole (`read_all`),
  tokenizes it with `json-tokens`' `token` (copied: it is a corpus program, not a library), and
  prints the value of the top-level key named by its second argument (a string's body, a number,
  a word). `data-json-vec`'s `Json` is not used: the example needs one field, not a tree; the
  tokenizer reaches as far as the milestone (#67 milestone 1) needs.
- `corpus/fs-fake.bc`: `fs-cat`'s loop and `json-field`'s read (`read_all`; the tokenizer is not
  copied a third time), each written over `Fs` and given it
  by its row) run under `fake_fs`, a handler of `Fs` whose state holds one readable file's bytes,
  a read position, and the bytes written to the one writable file: lawful by construction (its
  `fs_read` copies the next bytes into the spare room, its `fs_write` appends). Also `copy_file`, the
  two-file program over the operations' sums (section 3), and the fake's errors (an open of an
  unknown path, a read of a writable file). Run at every stage, the source stage included, with no
  host file.
- `corpus/fs-copy.bc` (added by the diff review): `copy_file` over two paths given as arguments,
  which `scripts/check-fs.sh` runs over a longer file it truncates.
- `corpus/reject/fs-two-files.bc`: `copy_file` with a raising call unhandled while a file is open,
  refused. `corpus/reject/fs-loop.bc`: a `File` in a `loop`, refused.
- `fs-cat` opens with `fs_open`, which hands the path back with the error, so it can name the path
  in its message.
- **Their corpus goldens.** `fs-cat` and `json-field` are corpus programs like any other, with
  `.args` naming `corpus/no-such-file`: every stage answers the error path with the same output,
  `fs-cat: corpus/no-such-file: not found` (the model: no files; Wasm: no preopen covers it;
  native: no such file). The success path is `scripts/check-fs.sh`'s.
- **`scripts/check-fs.sh`** (a gate step, `"fs files"`): makes a directory under the step's own
  temporary directory, writes a text file (with a multi-chunk one of 200 000 bytes) and a JSON
  file into it, and runs `fs-cat` and `json-field` on their absolute paths: in Wasm (`bcc run
  --dir <dir>`), natively (`bcc run --native`), and by `Backend2` where it runs them; each output is
  compared with the bytes written (fs-cat) or the expected field (json-field). It also runs a
  missing path and a directory. No network, no kubectl.
- **System calls, measured.** Not in the gate (the trace format of `wasmtime` is not a stable
  interface): measured once for the PR, with the `wasmtime` version named, from its trace of WASI
  calls: `fs-cat` on an `N`-byte file makes `floor(N / 65536) + 1` `fd_read`s, one `path_open`,
  one `fd_close`, plus the open's preopen walk (`fd_prestat_get` and `fd_prestat_dir_name` per
  preopen, the stated exception to one call per operation). Natively the count is read off the
  runtime's code (each function one call); a `dtruss` run needs root.

## 8. NOT in this unit

- No async (`#750` unit B), no `await`; no seek, no append mode, no directories (list, make,
  remove), no rename, no metadata beyond the size, no permissions argument, no symlinks.
- No path type: a path is a `string` of bytes, as the host takes it.
- No `Net` (#597).
- No `main_fs_error` ambient handler (as `main_div_error`): a program handles `Fail[FsError]`.
- No I/O in a `finally` (SPEC §42 *Open*, #746): the library closes on error itself instead.
- No caching of Wasm's preopen walk.
- No constructor privacy for `File` (*Forging*).

## 9. Tempting shortcuts → STOP

- **Glue outside externs**: a C or WAT helper that does more than the extern's one call and its
  error mapping (buffering, a path table, retries other than `EINTR` and a short write). STOP.
- **A borrow held across a pending operation**: an operation whose signature takes a view
  (`array_imm`/`array_mut`), as `Stdin`'s `input_into` does. Every `Fs` operation takes the owned
  `string`. STOP.
- **A hidden copy**: the clause copying the buffer to or from a scratch array, or `read_all`
  reading into a chunk and appending. STOP.
- **An implicit close**: the checker or the elaborator closing a `File` at the end of a scope.
  That is a drop that is not derived (SPEC §42 *Not this*). STOP.
- **A model that reads host files** (the interpreters doing `IO.FS`), or one golden per target.
  STOP: the model is the empty file system at every interpreted stage.
- **An unbounded `loop` holding a `File`**, or any sugar that lets one by changing `loop`'s close
  branch to drop or close its state: a drop that is not derived. STOP.
- **A new kernel former or rule** (a `File` kind with its own rule, a linearity check in the
  elaborator). STOP.

## 10. Review

One independent review (lens: shortcuts against principled design; fit with decision 71 and L-D).
It found the capability pattern and decision 71 followed, no kernel former needed, and:

- **Fatal F1**: an unbounded `loop` cannot carry a `File` (its close branch drops the state).
  Applied: every loop over a file is counted with stated fuel (section 3), STOP entry (section 9).
- **Fatal F2**: with two files open, a raising form is refused. Applied: stated as a limit
  (sections 3, 8), a two-file program over the sum forms and a reject program (section 7).
- **M1** forging: the fix is constructor privacy, not nominality; the guarantee restated (section 1).
- **M2** sizes past `2^31 − 1`: an error (now `TooBig`, section 2).
- **M3** `close` is not retried on `EINTR` (section 6).
- **M4** the laws allow an error everywhere; the model's `NotFound` for writing justified (sections
  2, 5).
- Minor: relative preopen names, the `fs_read` `0` wording, the trace not in the gate, the shared
  contract of size and close, two draft-code fixes: applied.

A second full review (the first had found Fatals) found no Fatal, and three Majors, applied:
running out of fuel raises `TooBig` after closing the file (no silent truncation); the two-file
limit restated as SPEC §42's handled-inside pattern, `copy_file` over the operations' sums, the reject narrowed; and
`read_all` raises `TooBig` before its buffer passes `2^31 − 1`. Minors applied: `reserve`'s real
growth, `corpus/reject/fs-loop.bc`, fs-cat's path through `fs_open`.

The diff review (one fresh reviewer) found no Fatal and two Majors, applied: the special case of
descriptors below `3` is dropped (it covered a few descriptors and left Wasm's preopens exposed;
the gap is constructor privacy, *Open*), and the gate now writes on a real host
(`corpus/fs-copy.bc` in `scripts/check-fs.sh`, truncating a longer file). Minors applied: an empty
path is `NotFound` on both targets, a path holding a `NUL` byte is `NotFound` natively, a FIFO
case reaches `read_all`'s growth natively, the skipped native runs are named in the summary, and
`fs-cat` no longer sums its counts.
