# An executable model of effects as algebras, capabilities as comodels

Phase A of #235. Experiment: `experiments/EffModel/` (non-default library `EffModel`, imported by
nothing, no Mathlib). It changes nothing in `Core/`, `Frontend/` or `Backend/`. Phase B (the
relation, the theorems, resource safety and the lift plan) is §8, over
`experiments/EffModelRel/`.

**Question.** Today's effect system is two mechanisms joined by glue:

- answering effects are borrowed capabilities (#184);
- control effects are §19 native capture by static name and site;
- the glue is `withCtl`, the unwinding borrows, and copies per row.

Higher-order use failed (#233): passing, returning or storing effectful computations, and
callbacks that take callbacks. Does a design built from one structure have the properties we
want? That structure is adjoint modes, effects as models, capabilities as comodels, running as
their tensor, and instances generated by `ν`. This is checked here in a small executable model,
before any kernel surgery.

**How claims are marked.**

- **[run]**: a `#guard` in `experiments/EffModel/EffModel/Tests.lean`, checked when
  `lake build EffModel` runs. The rows are typing judgements (`typecheck`) and runs of the
  definitional interpreter (`run`, fuel 20 000). No theorem is proved; this is phase A.
- **[paper]**: the cited paper states it, and I read the passage (section or line given).
- **[inferred]**: my reading, not established by a source or a test.

---

## 0. Answers

- **Tests.** Every acceptance test passes [run]:
  - 21 laws over 952 contexts (878 typed);
  - 10 programs;
  - 11 refusals, each with an accepted control.
- **One rule does most of the work.** Adjoint logic's declaration of independence, "a thing at
  mode `m` depends only on hypotheses at modes `≥ m`", is applied unchanged at every place
  something is captured: a thunk, the rest of a `to`, an argument waiting on the stack, a
  handler's clauses, a `using` frame, and an operation's continuation. Four of our scattered
  rules fall out of it:
  - the multi-shot persistence condition;
  - "no capability without a destructor across an affine operation" (4.A);
  - "`!` closures capture only persistent values";
  - the clause-capture rule (#216).
- **Continuation qualifiers are modes.** An effect's bound (§1.3) carries the qualifier into
  the type of each instance.
- **Instances (`ν`) remove static names.** They also remove per-row copies and the effectful
  callback rejection (#161).
  - `retry`, policies, callbacks taking callbacks, stored computations and objects with
    effectful methods all type and run, with no rule written for any of them.
  - Abstraction safety (no accidental handling) holds by construction.
  - Staton's four instance laws hold in every context.
- **Rules that do not fall out.** Five things needed explicit rules (§4):
  - **T1.** A lend's body must not perform an operation whose handler may keep the
    continuation. "May keep" is decided by a syntactic tail-resumption test on the handler's
    clauses.
  - **Second-class instances.** An instance is never data. Thunks may not capture a lent place
    or a frame-owned resource.
  - **The weakening point of a continuation.** A continuation is weakened (its destructors
    run) at the end of the clause that drops it. This is operational, not elaborated.
  - **A stored generator needed a `ν`-type and an explicit `drop`.** Without a recursive type,
    no continuation can leave its clause.
  - **Effect-free co-operations.** The comodel side is restricted to these.
- **Mapping verdicts** (§2):
  - **Confirmed:** adjoint modes and independence; models and handlers into any computation
    type; comodels as state access; the tensor as running; instances and `ν`;
    destructor-algebraicity; signals as decision C.
  - **Inferred:** continuations as mode-`m` thunks; the shifts `F`/`U`.
  - **Failed, adapted:** borrow as a mode. It is kept alongside the modes as a scope.
- **Cost.** The zero-cost lowering survives where it exists today (§6):
  - capability operations and tail-resumptive clauses lower to direct calls;
  - aborts lower to branches with landing pads;
  - suspending handlers lower to state machines.

  One new cost appears. An instance passed as a value means an operation on it is an indirect
  call through the instance, where today it is a static copy per site. It specialises back to
  a direct call where the instance is known.

## 1. The model

### 1.1 Syntax (`Syntax.lean`)

A call-by-push-value calculus with names.

- **Value types:**
  - `unit`, `int`, `bool`, `void`;
  - `prod`, `sum`;
  - `thunk m ρ C`, a suspended computation at mode `m` that performs `ρ` when run;
  - `inst E b`, an instance of effect `E` whose continuations are bounded by `b`. It is second
    class;
  - `cap E S`, an owned capability: a comodel of `E` with state `S`. It is linear, with no
    destructor;
  - `resD`, a handle on a frame-owned resource with a destructor;
  - `ticket`, a relevant token;
  - `stream ρ A`, `νX. U ρ (F (A + int × X))`, linear.
- **Computation types:**
  - `F A`;
  - `(x : A) ⇒ρ C`, dependent only when `A` is an instance type;
  - records `C₁ &ρ C₂`, each method with its own row;
  - bounded row abstraction `∀r ≤ b. C`.
- **Rows** are sets of instance variables and row variables. They sit where effects happen:
  after an argument is received, after a record is projected, before `F` returns.
- **Effect operations.** `op_x(v; y.M)` is the algebraic operation at *any* computation type.
  `perform` is its generic form.
- **Binders of instances:**
  - `handle x : E with H in M` is `ν x` plus a deep handler into any `ρh, C`;
  - `handleAt x H M` handles an instance already in scope;
  - `nu x M` generates an instance;
  - `ieq x y` is Staton's `?=`;
  - `lend c as x in M` runs `M` against the owned capability `c`: the comodel–model tensor.
- **Resources:**
  - `using x = acquire n in M`: a frame owns the resource and runs its destructor;
  - `drop s`: a stream's destructor.

### 1.2 Typing (`Typing.lean`)

`check Γ M` synthesises the row, the type, and how often each variable is used. Every property
rests on four checks.

1. **Grades.** Uses are intervals over `{0, 1, many}`. Sequencing adds them; branches (`case`,
   `if`, the methods of a record, alternative handler clauses) take the hull. A mode admits a
   grade when "never" or "sometimes" implies weakening and "many" implies contraction. These
   are the interval grades of `experiments/Grades`.
2. **Independence** (`Ctx.capture`). Every captured variable has a mode `≥` the capturer's.
   The capturer's mode is:
   - **a thunk at mode `m`:** `m`;
   - **the rest of a `to`, an argument frame, a handler's clauses, the algebraic
     continuation:** `Bound.req` of the row that may run meanwhile, i.e. the structural rules a
     handler may apply to the continuation;
   - **a `using` frame:** the frame is affine, so the row may not duplicate it;
   - **a resuming clause:** it runs once per operation, so its captures are unrestricted. The
     return clause and the abortive clauses are alternatives. If a resuming clause may drop its
     continuation, the return clause may not run.
3. **Scope.**
   - An instance never appears in a type outside its binder.
   - Instances and frame-owned resources are not first class.
   - A lent place is not used inside its lend, and no thunk captures one.
4. **T1** (`lend`). A lend's row must not have `Bound.susp`.

**The bound of an instance** (`Bound`, `handlerBound`).

- `req` is the union of the effect's continuation qualifiers. An abortive operation counts as
  affine.
- `susp` is true when the handler may keep a continuation past the operation. That is the case
  when:
  - some resuming clause is not tail-resumptive (`Tm.tailOnly`: `k` occurs only at the head of
    a call in tail position), or
  - the clauses perform an operation of `ρh` whose handler may keep its continuation.
- A runner's instance has bound `none`: nothing is captured, ever.
- A row variable carries a declared bound. `rapp` checks it.

So one type, `inst E b`, covers both implementations. A function that asks for
`inst Log ⟨lin, false⟩` accepts a runner's instance or a tail-resumptive handler's.

### 1.3 The machine (`Eval.lean`)

A CK machine. The stack holds these frames:

- `arg`, `bind`, `prj`;
- `handle i`, the handler of instance `i`;
- `runner i cell`, a lend of a capability;
- `coopRet`;
- `fin n`, a destructor frame;
- `clauseEnd k`.

An operation on instance `i` finds the nearest frame for `i`.

- **A runner** calls the co-operation on the cell's state, in place, and continues: a direct
  call, with no continuation.
- **A handler** reifies the frames above it, and itself, as `κ`, a store object with a status.
  It then runs the clause.
  - For an **abortive** operation it first **cancels** `κ`: it runs `κ`'s `fin` frames,
    innermost first, and nothing else. No handler inside `κ` sees the cancel (decision C).
  - For a **resuming** operation it pushes `clauseEnd`. When the clause returns, a `κ` that was
    neither resumed nor returned is cancelled.

Instances come from a counter (`ν`). The observable is the outcome, rendered with no instance
number, the world trace (`out n`, `acq n`, `use n`, `free n`, `punch n`), and the leaks
(resources not freed, capabilities never consumed).

Every row is a `#guard` [run]. The matrix is printed by `lake build EffModel`.

### 3.1 Laws

**The suite.** For each law, every permutation of its free instances (which binder is
outermost), every combination of their implementations, and four inner frames around the hole:

- nothing;
- a `using` frame whose destructor is observable;
- a `to` that emits the answer;
- a handler of an unrelated fresh `Fail` instance, which must not catch anything.

The implementations are:

| effect | implementations |
|---|---|
| `Log` | printing handler; writer (a handler into `int → F (A × int)`); runner over an owned capability |
| `Fail` | to an option; to a default |
| `Yield` | printing; summing (into a function type); take-1 (drops `κ`) |
| `Choose` | all-ways sum (resumes twice); first |
| `Ctr` | runner |

**Equality.** Two terms are equal in a context when their observables are equal: outcome,
trace and leaks. A law is checked only in contexts where both sides type, and no context typed
one side but not the other. A law that should hold only in some contexts states which, and the
check is that it holds in exactly those.

**Breadth, honestly.**

- Contexts are closing contexts built from a fixed set of handlers, runners and frames. They
  are not all contexts.
- The hole is always at `F int`.
- Every implementation is first order in its answers.

This is a test of the laws, not a proof.

**Why some contexts do not type.** Every untyped context is refused for one of the reasons
below; none is an accident of the suite.

- **An owned capability inside a region that may abort.** A `Log` or `Ctr` runner is placed
  inside a `Fail` handler. The runner's owned capability would be live across a computation
  that may abort, and it has no destructor (independence at `aff`). This is the reason in
  every arity-0 row and in the "lent state" row.
- **The multi-shot row:**
  - a `using` frame under `Choose` (a destructor frame at `unr`);
  - an owned capability under `Choose` (`lin` at `unr`);
  - a runner inside a multi-shot handler (T1: the all-ways handler is not tail-resumptive).

**Sum and tensor.** Both are visible directly.

- **Two writers commute; two printers do not.** A pure model's operations commute; the world's
  do not.
- **A lent capability's state survives an abort.** That is the coproduct, and it is what makes
  `retry` over a lent capability meaningful.
- **The absorption equation holds only where the program says it should.**

**The generator decision.** The resource is owned by a `using` frame inside the generator, and
that frame is in every continuation captured at `yield`.

- **Push.** A consumer that stops drops `κ`, which cancels it and runs the destructor.
- **Pull.** The generator is a `stream`, the continuation returned by a handler that keeps it.
  A stream is **linear**: it is pulled to its end or `drop`ped, and `drop` cancels the
  continuations it holds. That is the `A & 1` encoding: our `κ = ⟨resume, cancel⟩`.
- **Why the stream is linear.** If streams were affine, an implicit weakening would have to run
  the destructor. The model has no static weakening points (§5), so the destructor is made
  explicit.

## 4. What fell out, and what needed rules

**Fell out of the structure,** with no rule written for it:

- **Algebraicity at every computation type.** At `to`, at function types, at records, at
  arity 0. It comes from CBPV's stack semantics.
- **Handlers into any computation type, and forwarding.** The stack semantics again; rows sit
  on the judgement, so forwarded effects need no annotation.
- **Multi-shot persistence** (Tang et al.): independence at `unr`.
- **No capability without a destructor across an affine or abortive operation (4.A):**
  independence at `aff`.
- **The clause-capture rule (#216):** independence, with a resuming clause read as an
  unrestricted thunk. Only the grouping of clauses into alternatives was written by hand.
- **`!` closures over an `int` (#9, inventory 4.C):** an `int` is unrestricted, so an
  unrestricted thunk captures it. The `mkTimeout` policy does exactly this.
- **The relevant mode.** It needed no new mechanism: the grade and independence checks read
  `σ = {C}` like any other.
- **Abstraction safety, Staton's laws, and disjoint capabilities commuting.** Instances are
  generated, and runners hold separate cells.
- **Log/Fail sum versus tensor.** The nesting order alone gives it.
- **`retry` over a lent capability.** The lender's frame is outside the handler's, so the state
  survives.
- **Every #161/#233 program.** The kernel types computations as values already (§19 *Types*).
  What blocked them was static names and per-site copies, and instances remove both.

**Needed explicit rules:**

- **T1, and the tail-resumption test that decides `susp`.** Without the test, T1 refuses a lend
  under any handled `Log`. Without T1, `t1Harm` goes wrong.
- **The argument-frame check in `app`.** It is independence, but it needs a row on the
  judgement for the effects a function performs before taking its argument. With rows only on
  `F`, a handler into a function type holds its argument on the stack while its body runs.
- **Scope rules:**
  - instances and frame-owned resources are second class;
  - thunks capture no lent place;
  - `handleAt` respects the bound declared at `ν`.
- **Where a dropped continuation is weakened.** It happens at the end of the clause, unless the
  clause returned it, and abortive operations cancel before their clause runs. These are
  operational choices, not consequences.
- **The stream type and `drop`.**
- **Effect-free co-operations.**

## 5. Open problems

1. **Static weakening points for continuations.** The machine decides at run time, by
   reachability, whether a clause dropped `κ`. Congard et al. place destructor calls at
   weakening in the typing derivation; the elaborator should emit them.
   - Until it does, an affine thunk holding a continuation leaks when dropped.
   - The model sidesteps this by making `stream` linear with an explicit `drop`.
2. **Recursive and codata types.** Only the one `stream` type exists. Without it, no
   continuation can leave its clause: the clause's type would contain itself. So T1 is
   observable only through it.
3. **Co-operations with effects.** Ahman–Bauer runners raise exceptions and send signals from
   co-operations; here co-operations are pure state access. A failing capability (an I/O error)
   needs them.
4. **Reborrowing.** A lend of a borrowed capability is not modelled, nor `Imm` versus `Mut`.
   - "Lent versus owned" is checked syntactically, with no lifetimes, as the brief allowed.
   - Whether BoLo lifetimes can replace T1's syntactic test (a `κ` whose type mentions `'l`
     cannot be resumed after `'l`) is untested.
5. **Rows are per instance, not per operation.** A lend inside a handler of an effect with one
   suspending operation refuses even its tail-resumptive ones.
6. **The tail-resumption test is syntactic** (`Tm.tailOnly`). A clause that resumes through a
   helper is classified as suspending.
7. **Polymorphism.** There is no value-type polymorphism, so the programs are monomorphic in
   their answers. Instance arguments must be variables.
8. **Failing finalisers.** Destructors here only emit, so the K3 policy (a finaliser's raise
   supersedes) has nothing to say.

## 6. Cost sanity (design notes, not measured)

| construct | lowering | today |
|---|---|---|
| operation on a runner instance (capability) | direct call of the co-operation on the cell | same as `withswap` answering handlers |
| operation on a tail-resumptive handler (`susp = false`, `κ` linear) | direct call of the clause, returning to the perform site; no `κ` reified | §19 *Lowering* already does this |
| abortive operation | branch to the handler, destructors as landing pads, LIFO | same |
| suspending handler (stream), affine `κ` | state machine; `κ` is the frame record | same as §15 generators |
| multi-shot handler | `κ` copied: heap frames | not zero cost, today or here |
| `ν`, instance parameters | an instance is a pointer to its frame or cell; an operation on an instance not known statically is an **indirect call** through it | today: a static copy per site, a direct call. Specialising an instance known at the call site recovers the direct call; this replaces per-row copying as an optimisation rather than a requirement. |

### 8.1 The calculus, re-stated

Phase A's calculus, intrinsically typed (`Syntax.lean`), so that a term is its typing derivation
for everything but modes:

- **Contexts.** An instance context `Ψ` (instances are second class: a variable of `Ψ` is never
  a value) and a value context `Γ`.
- **Bounds.** Thunks, functions and streams carry an effect bound `Eb = (req : Mode, susp :
  Bool)`: the least qualifier of what they may perform, and whether a handler of it may keep its
  continuation.
- **Continuations.** `κ` has type `kty q b r C`: at an operation whose qualifier has weakening
  (`q.w`) it is the linear record `⟨resume, cancel⟩`, the `A & 1` encoding of §3.2. This is static
  destructor placement (§8.6).
- **Recursion.** Only `bfix x a v n M`, the `n`-th iterate of `M` from "abort `a` on `x`"; and
  one recursive type, the stream `strm b A = μX. U(F(A + int × X) & F 1)`.
- **Co-operations may raise.** A comodel's co-operation answers `coRes = (res × s) + (int × s)`.

**Denotation** (`Tree.lean`, `Denot.lean`). A computation denotes a finite tree with nodes
`ret`, `op i e o v k d`, `ab i e a v d`, `nu k` and `act a k`:

- `d` lists the destructors between an operation and its eventual handler. Cancelling the
  continuation runs `d` and nothing else (decision C).
- Every computation type is a model: an operation at a function or record type acts pointwise.
- A handler is the fold of a tree into a model (`Tree.hnd`), a lend the state-passing fold
  against a comodel (`Tree.runL`), and `finally` an `addFin`.

There is no fuel: `bfix` is bounded, so every definition is structural.

**Contextual equivalence** (`Obs.lean`). `CtxEq M N` quantifies over every syntactic closing
context `P : Context S Ψ Γ C g` at every ground type `g`, and compares the observables of the
closed programs: outcome (value, unhandled operation, or stuck) and trace (output, acquire, use,
free, create, consume).

### 8.2 The binary relation

**Worlds** (`World.lean`) are Staton's `[Inj, Set]` reading of `ν`, extended so that two sides
may allocate in different orders. For each name on each side the world says one of:

- `free`: not yet allocated;
- `m b`: matched with name `b` on the other side (a partial bijection);
- `p`: allocated, waiting to be matched later;
- `g`: garbage, never to be matched: an instance nothing can name.

The Kripke order `le` matches more names and frees fewer, with pending names unchanged. Values
are related at the world with pending names read as garbage (`gcP`).

**Trees** (`Rel.lean`). `TreeRel R w t t'` is an inductive relation: same shape up to the
world's matching of names. The constructors:

- `ret`, `op`, `ab` and `act` relate equal shapes. Operations and leaves need a world with
  nothing pending.
- `nu` matches two allocations. `nuL`/`nuR` and `mL`/`mR` let one side allocate first and match
  later; `gL`/`gR` let a side allocate a name the other never does.
- `abE` relates an abort carrying destructors `d ++ f` to running `d` first and then aborting
  with `f`. This is the destructor form of arity-0 algebraicity.

**Values and computations.** `VR` is defined by recursion on value types, `CRU` on computation
types, both Kripke at functions, instance abstractions and thunks. The stream type is the one
place a type mentions itself. Its relation `StrmRel` is the least relation closed under one
unfolding, an impredicative least fixed point; it exists because `X` is positive. Instance
environments are related by the world's matching (`IR`), value environments by `VR` (`ER`).
`LR M N` is the open relation.

**Theorems.**

- **[proved] The fundamental property**: `fundamental : LR M M` for every term (`Fundamental.lean`).
  It rests on the compatibility of the relation with every model operation, `bind`, handlers,
  lends and `finally` (`Compat.lean`: `hnd_rel`, `runL_rel`, `addFin_rel`, `bindC_rel`).
- **[proved] Soundness**: `soundness : LR M N → CtxEq M N` (`Adequacy.lean`). Adequacy runs two
  related trees against two worlds kept in step by an invariant (`Inv`). Related actions
  execute alike (`AR.exec_rel`), and related destructor lists unwind alike (`DR.unwind_rel`).
- **[proved]** `CtxEq` is an equivalence (`CtxEq.refl`, `symm`, `trans`), and denotational
  equality implies it (`CtxEq.of_den`).

**Step-indexing was avoided.** Trees are finite because recursion is bounded (`bfix`), so
`TreeRel` is inductive and `VR`/`CRU` are structural. The stream's relation is a least fixed
point, which needs positivity and nothing else.

**[proved] Where the method stops** (`Obstruction.lean`). Take a recursive type with `X` to the
left of an arrow under `U`, such as `μX. U(X → F bool)` (T15's "X under a `U`-codomain"). It has
no set denotation in this semantics. `no_negative_domain` shows that no set `X` retracts onto
`X → Tree S Bool`; it is Cantor's argument. Admitting that type is exactly what would force a
step-indexed or domain-theoretic model. The theorem is about this method, not about the type's
soundness.

### 8.4 Resource safety (unary)

**Ownership** (`Own.lean`). Ownership is a multiset of tokens: one per `using` frame's resource,
one per owned capability. The inductive `TS` says what a tree does with what it owns:

- acquiring and creating add a token; freeing and consuming remove one;
- reading and writing a cell need its token;
- at an operation, the continuation keeps everything owned. If the operation's qualifier has
  weakening, the destructors `d` free exactly what it owns (`CancelOK`, `DropOK`). If it has
  contraction, it owns nothing;
- an abort's destructors free exactly what it owns.

`Tree.Safe` runs a tree against the world with a ghost count of live tokens. `adequacyU`
proves that a `TS` tree runs safely.

**Values** (`Unary.lean`). `VS A O v`: the value `v` owns `O`. A thunk or a stream is safe at
its bound: forcing it gives a `TS` tree bounded by the bound's mode.

**[proved] The key lemma is independence**, `VS.indep`: a value at a mode with weakening or
contraction owns nothing. A continuation that may be dropped or copied therefore captures
nothing that owns. That is the whole content of the multi-shot persistence condition, of "no
destructor-less capability across an affine operation", and of "`!` captures only persistent
values".

**The judgement** (`ModedJ.lean`). `VM`/`CM` is phase A's typing on the intrinsic terms:

- grades: a linear variable is consumed once on every path;
- independence at every capture point;
- `using` frames are affine;
- bounds cover what is performed;
- rows are sets of instances with a mode for what thunks perform.

The fragment omits `lend`.

**[proved] The fundamental property** `CM.fp` / `VM.fp` (`UnaryFP.lean`): a moded term, in an
environment whose values own `Os`, is safe owning exactly what its linear variables own. The
tree-level lemmas it uses are in `UnaryCompat.lean` (`hnd_safe`, `mkK_safe`, `bindC_safe`,
`addFin_safe`, `dtorsT_safe`, and the model operations).

**[proved] `resource_safety`.** For a closed program `P` with `CM VSet.none R P`, the run of
`P` never fails an action. Every free, read, write and consume finds its token and a live cell.
If the run returns, nothing is live:

- every resource a `using` frame acquired was freed exactly once, whether on return, on abort,
  when a continuation holding the frame was cancelled, or when a stream was dropped;
- every capability was consumed exactly once.

The statement is:

    theorem resource_safety {g : G} (P : Prog S g) {R : Row S []}
        (hP : CM (Ψ := []) (Γ := []) VSet.none R P) :
        (P.den IEnv.nil Env.nil).Safe (fun O _ => O = 0) ⟨Wd.init, 0⟩

**What it does not cover:**

- **Lends.** The judgement has no `lend` rule (§8.5).
- **Effect safety.** An operation that reaches the top is not `Safe`'s business: `Tree.Safe`
  is `True` at a top-level `op` or `ab`. The judgement bounds what a thunk performs by a mode,
  not by a set of instances (`Row.fgn`), so it cannot conclude that a forced thunk's operations
  are handled. This is open (§8.8).
- **Use of a resource handle after its frame freed it.** A handle is second class by phase A's
  scope rule, and `use` checks no token.

"No stuck states" holds for actions: intrinsic typing excludes type errors, and `Safe` excludes
a failed action. It does not hold for unhandled operations, which is effect safety.

### 8.5 T1 and the tests that depend on it

**[proved] The harm T1 prevents is real.** In `t1Harm` (`Examples.lean`), a stream escapes a
lend through a handler that keeps the continuation. The owner then consumes the capability, and
pulling the stream resumes the runner, whose write-back finds no cell:
`t1Harm_stuck : t1Harm.obs.out = .stuck`. The control, a tail-resumptive handler, runs:
`t1Control_runs`.

**[open] T1 soundness.** The statement to prove is `resource_safety` for the judgement extended
with a `lend` rule whose body's row has `susp = false`, with the rule as phase A states it.

What is missing is not verified to be an obstruction. It is a mechanism the current proof does
not have:

- **Ownership is tree-local.** `TS` gives each token to one subtree.
- **During a lend, the capability's token sits with the runner frame**, inside every
  continuation the body's operations capture.
- **When the lend returns, the token must go back to the owner.** This is a lifetime-style
  return of ownership at a scope's end.
- **`susp = false` is not yet a semantic fact.** It has to become one: a handler whose bound
  says it does not suspend resumes or cancels `κ` before its clause returns, so no continuation
  holding the token outlives the lend.

Neither the debt bookkeeping in `TS`/`CS` nor that tail-resumption lemma is built.

The three tests that depend on T1 have this status:

- **The tail-resumption test.** Phase A's `Tm.tailOnly` is syntactic. Here it is the bound's
  `susp` bit. Its soundness is the tail-resumption lemma above: **open**.
- **"Instances are never data"** is **[proved] by construction**. Instances live in `Ψ`, which
  no value type mentions, and `ilam`/`iapp` abstract over them. `no_accidental_handling` is
  the parametricity this buys.
- **The stream type with `drop`** is **[proved] sound** for resources:
  - `StrmS` and the `fold`/`unfold` cases of `CM.fp`;
  - `drop` is the stream's `& F 1` component;
  - a dropped stream runs its continuations' destructors (`mkK_safe`);
  - in the binary relation, `StrmRel` and the fundamental property cover it.

### 8.6 The two settled questions

**Destructor placement: static** (Congard et al.). `κ` at an operation with weakening is the
linear record `⟨resume, cancel⟩` (`kty`). `cancel` runs exactly the destructors recorded at the
operation. The elaborator places `cancel` at each weakening point, so a dropped `κ` is a static
destructor call and the machine has no reachability test.

- **[proved]** The binary relation (`mkK_rel`, `hnd_rel`) and resource safety (`mkK_safe`,
  `hnd_safe`, `resource_safety`) hold with this placement.
- Phase A's open problem 1, "an affine thunk holding a continuation leaks when dropped", is
  closed by it.
- This is the kernel's `kTy` (`Core/EffRules.lean`): `U((B ⊸ F_Σ R) & F_Σ 1)` at `aff`. The
  kernel already has the static form.

**Co-operations that can raise: yes, by Ahman–Bauer's `finally`.** A co-operation answers
`coRes = (res × s) + (int × s)`: an answer and a next state, or an error and a state. When a
co-operation raises:

1. the runner cancels the client's continuation, running its destructors;
2. it writes the state back to the cell;
3. the lend answers `inr e`.

- **[proved]** The relation is preserved (`runL_rel`), and the resource side by
  `dtors_safe`/`dtorsT_safe`.
- The write-back is itself a destructor (`Dtor.wb`) on every operation the lend forwards. An
  abort that passes through the lend therefore also writes back first. That is
  `not_absorb_runner_inside` and `lent_state_survives`.
- **[inferred]** An operation whose co-operation can raise must have a qualifier with
  weakening, since its continuation may be cancelled.
- In the kernel this is `Row.Unwind` (`Core/EffBorrow.lean`): a borrow's callback may unwind
  through abortive operations, and the frame writes back.

### 8.8 Open items

1. **T1 soundness.** The statement and the missing mechanism are in §8.5. The harm is

6. **Use-after-free of resource handles.** A handle is second class by phase A's scope rule,

**[proved] Rows on types.** `Rw` replaces `Eb` on thunk, function and stream types: a list of

instances. The thunk's lifetime is the meet of the pairs' lifetimes (`Rw.life`, the innermost
level); its effect bound, the join of its instances' declared bounds, is recovered from the row
(`Row.mode`). Scope (`VTy.Sc`) says a type names only instances in scope; the moded judgement
checks it wherever a type enters (`CM.bind`, `CM.app`, `CM.handle`, …), and an instance's binder
then confines it. [inferred] In this calculus the lifetime of a pair is its instance's own level:
no rule reads the lifetime component beyond scope. It is where a borrow's lifetime would go.

relation's `runL_safe` carries the capability's token in the `run` frame.

### 9.2 Step 1: the ownership fragment

**Names in a continuation.** The tree semantics allocates a name when the run reaches its `nu`
node, so a name a continuation allocates after its capture point is fresh at each resumption: the
α-renaming at resume is the semantics. A name allocated before the capture point and still
pending is shared by every resumption. Staton's `ν/op` moves a `ν` from the first kind to the
second.

**`ν` under capture.** idem-ν, ν/ν and new-ν hold as before (`Laws.lean`). For `ν/op`:

- [proved] It fails in phase B's `CtxEq` at a **linear** operation too (`nu_op_fails_linear`):
  its contexts ignore modes, so a clause may resume a linear continuation twice, and phase B's
  multi-shot counterexample goes through unchanged.
- So O1 is a statement about moded contexts. `CtxEqM` (`Ownership.lean`) quantifies over the
  contexts the moded judgement accepts, and `O1 : Prop` states the law there at an operation
  without contraction. **[open] Not derived.** `TreeRel.op` relates an operation only at a world
  with nothing pending, so the left side's pending name must be read as garbage, and garbage is
  never matched with the right side's later name. A proof needs a binary relation in which a
  continuation value owns the pending names it will match, with a fundamental property for moded
  terms only. I have not derived O1 and have not verified that any obstruction is real.

**η, the forwarding handler.** In this calculus the forwarding handler is `handleAt x` with every
clause `op x.o(p; y. resume k y)`: the same instance, re-performed past the handler frame; no
renaming is involved.

- [proved] Semantically, a handler whose clauses re-perform each operation on the same instance
  **with the destructors it was performed under** is the identity on related trees (`fwd_id`).
- [proved] The syntactic clause re-performs with no destructors, so it loses those of the frames
  between the operation and the handler. At a linear operation that is observable only at an
  unhandled operation, where the stack unwinds (`eta_fails_linear`); effect safety excludes it for
  moded programs. At an affine operation it is observable when an outer handler cancels: the
  frame's resource leaks (`etaAff_obs`), and the program is not moded (`etaAff_not_moded`; the
  clause's continuation captures `k`, a linear thunk, at an affine operation).
- [inferred] η that forwards cancel, finalisers included, needs a forwarding primitive whose
  destructor is the cancel of `k`. Phase B's destructors (`Dtor`: free a resource, write a state
  back) are first order and cannot carry one; `fwd_id` is that primitive's law.

**[proved] Hiding, as parametricity** (`hnd_sim`). Two handlers into state-passing types, of
possibly different state types, whose clauses map related states to related computations given
related continuations, relate the handled trees at related states, for any related bodies. The
body cannot see the handler's witness. `hiding_counter` instantiates it: no body tells a counter
kept as `n` from one kept as `-n`. This is the relational form of BoLo's anti-frame for a
handler's state, the template an anti-frame for a borrowed witness would instantiate.

### 9.3 Step 2: a cell holding a continuation

**The model** (`Cell.lean`, namespace `EffCell`). A *place* is a cell that a computation creates
(`pnew`), resumes in place (`pnext`) and drops (`pdrop`); it holds a *generator*, phase B's
stream: a continuation captured at `yield`, with its cancel as the drop. Resources are acquired
and freed. Places are stratified by **level**: a tree at level `L` touches only places of level
`L`, and a place of level `L + 1` holds a generator whose trees are at level `L` (`St`). So a
place's content never touches a place of its own level, in particular not the place itself: the
cell's stratum excludes it. The run (`runK`) is by recursion on the level, then on the tree; no
step index, no fuel.

**[proved] The cell lemma** (`adequacy`, its `pnext` and `pdrop` cases). The invariant of a place
of level `L + 1` (`VSt`) is the least predicate closed under one unfolding: its generator's pull,
run at level `L`, answers done or an element and a rest that again satisfies it, and its drop
disposes of what it owns.

- *Resume.* The content is taken out (`Inv.takeOut`: the place is busy, and the run that resumed
  it holds its token as a frame), its pull runs at the level below under fresh names (`acq` and
  `pnew` take the world's next name), and the rest is put back (`Inv.putBack`). The rest satisfies
  the invariant because the invariant is a fixed point: re-rebasing is the generator's own type.
  A tree cannot resume a busy place: its token is held by the frame that resumed it.
- *Drop.* The content is taken out and its drop runs to completion; the place is freed
  (`Inv.freePl`).

**[proved] Safety** (`cell_safety`). A safe closed tree runs to an answer from the empty world,
never stuck, and at the end every resource is freed and every place dropped, including places
that contents created. The proof that nothing is left uses that strata order ownership: a
content owns places only below its own level (`VSt.below`), so the highest live place would have
no owner (`Inv.empty`).

**Tripwire.** `no_negative_domain` is unchanged and builds. [proved] Without strata, a place
holding a continuation is T15 in its exact form (`no_place_store`, `no_place_store_tree`): phase
B's denotation reads a cell's content as a value (`Act.rd`), and a tree type with a node reading
a place that holds a continuation over the same trees retracts onto its own function space, which
no type with a fixed-point-free map does (Lawvere's form of Cantor). The cell model avoids it
twice: the world runs a content rather than a tree reading it as a value, and the level makes
that run well founded. [inferred] With strata, the disguise the brief named (a cell's invariant
over continuations whose relation ranges over worlds containing that cell) does not arise:
`VSt (L + 1)` refers only to `TS` at level `L`, which cannot name a place of level `L + 1`.

**[proved] T1, on top** (`CellExamples.lean`). Borrows are tokens: `lend` turns an owned resource
into a reservation and a borrow, `reclaim` turns them back, `touch` uses a live resource. A
place's token carries its *return set*: the borrows its content gives back when dropped. A
generator that captures a borrow is stored in a place whose return set names it; the loan can end
only with the borrow back, so the place must be dropped first. `borProg` keeps that order and is
safe (`borProg_safe`, run `borProg_run`). `harmProg` frees the resource while the generator still
holds its borrow, then resumes it: the run is stuck (`harmProg_stuck`), so it has no safety
derivation (`harmProg_not_safe`). A continuation capturing a borrow is bounded by the loan because
what it holds must be given back, and that is the drop of the place that holds it. A generator
that owns its resource needs nothing of the kind (`ownProg_safe`).
