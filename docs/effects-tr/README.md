# The effect calculus: a technical report

A paper proof, written before the mechanisation and the kernel lift, for the effect calculus of
#235: adjoint modes, effects as models (handlers into any computation type), capabilities as
comodels (runners), instances generated by `ν`, destructors, and bounded recursion. The
mechanisation is meant to transcribe it step by step, the way borrow-core's `Paper/` transcribes
Wagner et al.'s [TR]. Issue #245.

The calculus is phase A's (`experiments/EffModel/`, `docs/effect-model.md`), written as **BoLo's
resource world plus a local control discipline** that meet at three points: capabilities are
resources, continuations are values in the resource world, and cancellation is finalisation.
Phase B's Lean binary relation (`experiments/EffModelRel/`, branch `effmodel-rel`) is the
cross-check: every result it has proved is cited by name, and nothing here contradicts it (§6.4).

## Conventions

- **Numbering.** `D§.n` definitions, `L§.n` lemmas, `T§.n` theorems, `C§.n` corollaries,
  `O n` open problems: separate sequences, prefixed so that no two share a name. [TR]'s numbers
  are cited as "[TR] 6.65" (a lemma or theorem) and "[TR] Def 6.1".
- **Citations of code.** `[PA name]` is a declaration of phase A's model, `[PB name]` of phase B's
  Lean, `Core/…` of borrow-core's kernel.
- **Proof status.** Every proof step names the definition or lemma it uses. A proof is one of:
  - *mechanised*: proved in Lean (phase B, or borrow-core `Core/`), cited by name; the proof here
    describes it;
  - *proved here*: written in full on paper;
  - *proved here at the level of its cases*: each case is written; the bookkeeping a mechanisation
    adds (typing of the decoding in T6.6) is not;
  - *open*: the statement, and the exact step that does not go through.
- **Math.** Plain Unicode in code spans and blocks: `⊢`, `⊧`, `●`, `⋆`, `⟦·⟧`. `≡` is contextual
  equivalence.

## Findings, in brief

1. **Three of phase A's typing rules let programs go wrong**, each machine-checked against phase
   A's model (§10): a lent place moved before the lend (stuck); a frame-owned resource carried past
   its frame by a continuation in a stream (use after free); a return clause that owns a
   capability run twice by a relevant operation (consumed twice). Each changed a rule of §2.
2. **ν/op holds only at non-contractible qualifiers**, as phase B found; the non-contractible case
   is open (O1), and it is the one place the factoring strains (§9.1).
3. **T1 is not needed for this calculus** once the lend owns its capability (T9.1). It is needed
   when a continuation may hold a *borrow*, which is the kernel lift (T9.2, O2, O3).
4. **The calculus uses only BoLo's own-fragment.** Lifetimes and borrows enter only at the lift
   (§9.1 item 4).
5. **No step-indexing**, because recursion is bounded and the one recursive type is positive
   (§9.4). What would force it is listed there.
